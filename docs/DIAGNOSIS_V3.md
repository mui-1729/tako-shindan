# 診断設計 v3 — 身近で笑えて、採点には一貫性がある8問

## 変更概要
診断の4軸、0/33/67/100の得点、16タイプの対応、結果を公開する3人閾値はv2から変更しない。v3は**新規作成したリンクだけ**で使う。過去のv1/v2の回答とは混ぜない。

「○○だったらあいつ絶対こうする（笑）」と自然に想像できる会話・LINE・サークル・学祭の場面を採用。答える人が本人の内面を推測するのでなく、**先に見えやすい行動や発言**を選ぶ。

## 測定する4軸
| 軸 | 左=0 | 右=100 |
|---|---|---|
| 会話の入り方 | 自分から会話を始める | 他の人から始めるのを待つ |
| 物事の進め方 | まず動く | 先に確認・準備をする |
| 物事の選び方 | 新しい案を選ぶ | 既存の案を磨く |
| 助けるときの初動 | 最初に感情を受け止める | 最初に一緒に対策を考える |

どちらが上という軸ではない。同じ人が状況によって左右を行き来することもある。

## v3の全8問

1. **みんなで遊んでいて、会話がふと止まった。この人は？** 自分から話題を切り出す(0) / 質問して始める(33) / 誰かが始めたら乗る(67) / 振られるまで様子を見る(100)
2. **集合10分前、集合場所が突然変更！ この人は？** とりあえず動く(0) / 場所だけ確認(33) / 行き方確認(67) / 道順と時間を決め直す(100)
3. **サークルの企画が毎回同じ。この人が提案しそうなのは？** 全然違う企画(0) / 大きな新要素(33) / 前回の企画を工夫(67) / 好評だった企画を磨く(100)
4. **友達から「今日の発表、盛大にやらかした…」と来た。最初に返すのは？** 気持ちを聞く(0) / 大変だったねと状況を聞く(33) / 困ったところを整理(67) / 次の具体策(100)
5. **初対面の人と同じ班になった。この人の最初の動きは？** 話しかけられるまで待つ(100) / 声をかけられたら入る(67) / 自分からあいさつして始める(33) / 自分から話題を振る(0)
6. **学祭当日に急な追加作業！ この人なら？** 作業の順番を決める(100) / 必要なものを確認(67) / 最低限聞いて始める(33) / まず手を動かす(0)
7. **いつもの遊び方がマンネリ気味。この人なら？** 定番を磨く(100) / いつもの遊びに小さな変化(67) / 少し違う遊び(33) / 完全に新しい遊び(0)
8. **友達が「課題が終わらない！」とSOS。この人の第一声は？** 優先順位を決める(100) / 難所を整理する(67) / 大変だねと状況を聞く(33) / 焦るよねとまず聞く(0)

各軸は2問。選択肢の順は5〜8問で反転させ、並びだけで同じ選択を繰り返す影響を多少抑える。「わからない」は維持、6/8回答・各軸最低1回答。SNSでしか交流のない人は観察できない場面をスキップしてよい。

## 数値と解釈
各軸で回答された問題の点の平均を求め、50点以上か未満の4ビットで16動物に分類する。これは心理学的な性格検査の基準ではなく娯楽上の便宜。

「49点と50点で別の動物になる」問題を補うため、いずれかの軸が50点から10点以内なら、その軸だけ反転した『近いタイプ』も表示する。結果はキャラ以上に4軸の傾向を重視し、少人数の結果には必ず暫定性を表示。

## 運用・保護
- v1/v2リンク：旧設問・採点・タイプをそのまま維持
- v3リンク：新しい8問・同じ4軸・16動物
- 管理者だけが受付を停止・再開・データを完全削除できる
- 同一診断への送信試行は毎分120回まで。全サイトのBot対策としては不十分なのでTurnstile等は別途必要
- 統合テストで回答集計、認証、3人閾値、停止・再開、削除、SNSリンクメタデータを検証
- 学生10〜20人で実際に答えやすさとユーモア・判定納得度を検証することが次の課題
